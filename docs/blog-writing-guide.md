# 恋愛ブログ 執筆ガイド（人が書いた文章に見せるために）

記事本文は microCMS（と管理画面の Supabase columns）に入っているため、このリポジトリからは直接書き換えられない。
新しく書くとき・既存記事を直すときは、このガイドを横に置いて microCMS 上で手直しする。

目指すのは「情報がまとまった記事」ではなく「**恋をしている誰かが、友だちに話すように書いた文章**」。

---

## 1. いちばん効く5つの直し方

### ① 書き出しを「問いかけ」から「場面」に変える

AIっぽい記事は、ほぼ必ず「〜と悩んでいませんか？」から始まる。

- ✕ 好きな人からのLINEの返信が遅くて、不安になっていませんか？この記事では脈ありサインを解説します。
- ○ 金曜の夜11時。既読がついてから、もう40分たっている。スマホを伏せて、また表に返して——あの時間、何回くり返したか覚えていません。

**時間・場所・具体的な動作**を一つ入れるだけで、一気に「誰かの話」になる。

### ② 「まとめ」「いかがでしたか？」を消す

- ✕ いかがでしたか？今回は脈ありサインを5つ紹介しました。ぜひ参考にしてみてください！
- ○ 結局そのあと、彼から「寝落ちしてた」って返ってきて、40分の悩みは何だったんだろうと笑いました。でも、あのときの自分に「大丈夫だよ」とは、正直まだ言えない気がします。

最後は**要約ではなく、自分の気持ちか、その後の話**で終える。

### ③ 断言を減らして「私の場合は」を入れる

- ✕ 男性は本命の女性にはすぐに返信します。
- ○ 私の周りを見るかぎり、本命だから返信が早い、とは限らないみたいです。友だちの彼は、付き合う前は1日1通だったそうなので。

「〜です」「〜しましょう」の連続は教科書っぽくなる。**根拠の出どころ（自分・友だち・読者の声）** を一言添える。

### ④ きれいすぎる箇条書きを崩す

「ポイント①〜⑤」がきっちり並ぶと、それだけで量産記事に見える。

- 箇条書きは1記事に1回までを目安に。
- 項目数は3や5にそろえなくていい。4つでも、2つでもいい。
- 各項目の説明の長さをわざとそろえない。語りたいところは長く、そうでないところは一行で。

### ⑤ 失敗・迷い・よくわからないことを書く

人が書いた文章には「うまくいかなかったこと」と「今でもよくわからないこと」がある。

- 「これは正直、やらないほうがよかったです」
- 「ここは人によると思うので、私の答えは書かないでおきます」
- 「あとで友だちに話したら、それは考えすぎと言われました」

## 2. 避けたい言い回し（見つけたら書き換える）

| よく出る表現 | 書き換え例 |
| --- | --- |
| 〜と悩んでいませんか？ | （場面描写から入る） |
| この記事では〜を解説します | （消す。タイトルで伝わっている） |
| 〜することが大切です／重要です | 〜しておくと、あとで自分がラクでした |
| 〜しましょう！ | 〜してみるのもありだと思います |
| さまざまな／多くの人が | 私の友だち3人のうち2人は |
| ポイントは3つあります | 気をつけていたのは、だいたいこのあたりです |
| いかがでしたか？ | （消す） |
| ぜひ参考にしてみてください | （消す、またはその後の話で終える） |
| 〜と言えるでしょう | 〜なのかな、と思っています |
| 結論から言うと | （体験談記事では使わない） |

同じ語尾が3回続いたら、どれか一つを変える（「〜です。〜です。〜です。」→「〜です。〜なんですよね。〜でした。」）。

## 3. カテゴリー別のトーン

| カテゴリー | 書き手の立ち位置 | 目安 |
| --- | --- | --- |
| 実話・体験談 | 当事者。一人称で、時系列で語る | 会話文（「」）を2〜3か所入れる。オチがなくてもいい |
| 恋愛あるある | 友だちとしゃべっている感じ | 「わかる」と思ってもらう一文を先に。解説は短く |
| 恋愛スポット | 実際に行った人 | 行った季節・時間帯・混み具合・「ここは微妙だった」も書く |
| 恋愛コラム | 少し先輩の相談相手 | 一般論→自分の場合→読者への選択肢、の順。決めつけない |

---

## 4. 装飾の使い方（サイト側の表示ルール）

- **太字**：記事ページでは淡いピンクのマーカー線で表示される。1見出しにつき1か所くらいまで。全部に引くと読み飛ばされる。
- 引用（blockquote）：実際に言われた言葉・LINEの文面に使うと効果的。斜体にはならない。
- 丸数字（①②…）：自動でピンクの番号バッジになる。手順記事以外ではなるべく使わない。
- 見出し（h2）：「〜する方法」「〜の特徴」ばかりにしない。「40分後に届いたLINE」のような、中身を少しだけ見せる見出しも混ぜる。

## 5. 公開前チェックリスト

- [ ] 書き出しの3行に、具体的な場面（時間・場所・動作）がある
- [ ] 「私」「友だち」など、話の出どころがわかる一文がある
- [ ] 「いかがでしたか」「まとめ」「ぜひ参考に」が残っていない
- [ ] 同じ語尾が3回以上続いていない
- [ ] 箇条書きが1〜2回以内
- [ ] 失敗・迷い・例外のどれかが一つは書いてある
- [ ] 最後が要約ではなく、気持ちかその後の話で終わっている
- [ ] 抜粋（excerpt / SEO説明文）も「〜を解説」ではなく、中身が想像できる一文になっている

---

## 6. 注意

- 体験談カテゴリーでも、**実在しない人物の体験を本当にあった話として書かない**。聞いた話を再構成した場合は「友人から聞いた話をもとにしています」などと一言入れる。
- 読者の相談やコメントを載せるときは、本人が特定できる情報（職場・地名・年齢の組み合わせなど）をぼかす。
